## Primary findings

1. Two independent recovery layers were active. Of 166 llm/retry events, 155 came from standard DSH retry and 11 from Camel. At least one agent session spent over 15 minutes in repeated rate-limit recovery before manual cancellation.
2. Some FreeLLMAPI gateway cooldown failures were surfaced to DSH as RATE_LIMIT, despite an upstream request not necessarily being sent. Retrying the same disabled or unavailable route without checking status is not useful.
3. Some upstream rejections were **request-shape problems**, not quota pacing: an attempted ~9,595 input-token request exceeded a 7,000 ITPM allowance and produced a 413; a model received a 32,768 output-token request although its upstream maximum was 8,192 and returned 400.
4. Agent tool failures were separate from API failures, including Windows sandbox ACL failures and file-not-found errors.

## Changes considered next

- Assign **one owner for RATE_LIMIT retry**; do not let DSH and Camel independently multiply attempts.
- Let Camel pace exact (provider, model) routes; verify behavior with real tool-use tasks.
- Reduce inflated model context/output declarations when supported by actual quota evidence; note that contextWindow is **not** a strict HTTP input-token admission limit.
- Reduce redundant file operations and write task checkpoints before long-running changes.

## Evidence limits

The study cannot show that an altered profile improves end-to-end task success. That requires additional controlled or clearly labelled observational testing. The analysis was based on locally supplied DSH event logs; historical upstream quotas and provider health must be separately corroborated for future publication.
