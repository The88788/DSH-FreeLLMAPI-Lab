# План проекта и журнал прогресса

> Дата подготовки: **17 октября 2026**. Основной рабочий файл с чекбоксами и историей выполнения: [ROADMAP.md](ROADMAP.md).  
> Эта русская версия объясняет этапы. Для избежания расхождений актуальный статус задач всегда проверяем в основном файле.

## Цель

Создать независимую открытую лабораторию настройки **DeepSeek Harness + dsh-camel + FreeLLMAPI**, которая позволяет воспроизводимо исследовать реальные задания AI-агентов и улучшать надёжность при ограниченных квотах. Отвечать на вопрос «выполнена ли задача?» важнее, чем «ответил ли API на короткий запрос?».

## Правила проекта

- Конфиги **Experimental** не называем проверенными, пока не завершён реальный сценарий программирования с критериями приёмки.
- Не публикуем сырые журналы DSH, API-ключи, промпты, исходный код проектов, персональные пути и данные аккаунтов.
- Настройки не применяются автоматически: генератор предлагает патч, показывает diff, создаёт резервную копию, а решение принимает пользователь.
- Различаем RPM, TPM, ITPM, RPD, контекстное окно, лимит выходных токенов, блокировки каталога, cooldown шлюза и ошибки провайдера.
- Статус `completed` в DSH ещё не означает, что требования ТЗ выполнены.
- Каждое техническое заключение связываем с версией среды и проверкой. Неизвестные параметры обозначаем `unknown`.

## Первый эксперимент после создания репозитория

1. Зафиксировать версии DSH, dsh-camel, FreeLLMAPI и контрольные суммы исходных настроек.
2. Проверить, что **именно штатные retry DSH** отключены или ограничены; `/camel status` это не подтверждает.
3. Провести три разные реальные задачи: короткая с инструментами, средняя правка кода, длинная с контрольными точками.
4. После каждой задачи локально собрать результаты: проверка ТЗ, число ошибок и повторов, время до первого полезного инструмента, время ожидания, вмешательство человека.
5. Сравнить с исторической базой, не выдавая разные задачи и разные квоты за точный A/B-тест.
6. Оставить либо откатить изменения по результатам, записать вывод и добавить в основной `ROADMAP.md` строку журнала.

## Что уже выполнено

- **15–16 октября 2026**: проведён анализ 33 сессий, 4 028 событий. Выявлены двойной retry DSH/Camel, ограничения входа/выхода и ошибки инструментов. Сырые данные остаются приватными.
- **17 октября 2026**: пользователь подтвердил через `/camel status` загрузку восьми индивидуальных маршрутов Camel и `retry.enabled=false`; эффективность новой схемы пока не доказана.
- **17 октября 2026**: подготовлены локальная версия плана, примеры конфигураций и стартовая структура публичной лаборатории. Публичный репозиторий GitHub создан; стартовый комплект из 18 файлов размещён, проверка ссылок на GitHub и реальные тесты ещё впереди.

## Как обновлять план

Один файл `ROADMAP.md` является источником истины: отметить чекбокс только после проверки, добавить дату, результат, доказательство и следующий шаг. Issue и PR связывать ссылками. Русский обзор синхронизировать после значимых изменений, но **не вести два независимых списка выполненных задач**.
